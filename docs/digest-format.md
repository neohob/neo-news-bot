# 把候选压成一份日报

`collect.py` 只负责「抓 + 筛」。从 `candidates.json` 到一条能读的日报，还差一层编版——**这一层才是内容量的真正瓶颈**，不是源不够。

踩过两次坑，记在这里：

1. **每天两百多条原料，日报只有 3 条**。原因不是源少，是编版规则写了「压成 3-5 条」。
2. **改成「全收录」之后，日报里混进了「某源今日无新增」这种后台状态**。那是元信息，不是内容。

## 版式：像报纸，有头条有专刊

```
📡 每日情报 · <日期>

🗞 头条（3-5 条）
   每条四行：是什么 / 对你的用处 / 怎么拿 / 时限
   只给 obtain=free|conditional 且当天就能动手的，每条都要带链接

🔍 专题（0-1 条，可省略）
   当天候选里 ≥3 条指向同一主题时写 150-250 字：现象 → 对你的实际影响 → 一句建议
   末尾列 2-4 个相关链接。没有合适主题就整节省略，不许硬造

📌 要闻（12-18 条）
   两行：**标题** [链接](url) 换行一句「对你的用处」
   可以吃 info 类：新工具、新模型、行情、自建项目、额度变动

⚡ 快讯（剩下的全部，通常 45-65 条）
   一行一条：**标题** — 一句为什么值得看 [链接](url)，一句话不超过 35 字
   按 score 从高到低排

今日一句话（可选）
```

轻重比大约 1:1:2（按条数），按篇幅则头条占大头。实测一天 88 条、约 10000 字符，Discord 自动拆成 5~6 条消息。

## Agent 提示词模板

把 `candidates.json` 交给一个 agent 编版时，用这个（替换 `<...>` 占位符）：

```text
[执行纪律] 你必须立刻调用工具，不要输出开场白、计划或复述步骤。

你是 <使用者> 的「每日情报」主编。把当天候选池里合格的条目全部编进日报，
不设总量上限：有头条、有专题、有要闻、有快讯，轻重分明。宁可长，不要漏。

步骤1：terminal（timeout=600）执行：cd <项目目录> && python3 collect.py
步骤2：read_file 读 <项目目录>/candidates.json。item 字段：src、title、url、score、
       obtain（free/conditional/info/trial/lottery/promo）、codes、tags、extra。
       meta 里是每源条数，ERR 的源今天挂了不要提。
步骤3：编版（版式见下）。候选池已过噪音过滤，剩下的大约 80-95 条，几乎全部要用上。

标题日期用 [CURRENT RUN TIME] 里的当天日期，不要照抄模板里的日期。

<版式：复制上面那四段>

<使用者画像>（写「对你的用处」时对着它写）：
- 职业与技能栈、自维护的服务和硬件
- 在用哪些 AI 工具与模型
- 副业 / 内容方向
- 已经在监控、不要重复报的东西

分层规则：
- 同一件事只出现一次，头条/要闻/快讯不得重复。
- 快讯每行仍要写「为什么值得看」，可以极短（15-30 字），不能只贴标题。
- 不收录：obtain=lottery（抽奖）/promo（软广招募）；trial 非大厂不收录；
  会员领取、二手收售、求教帖、国内消费优惠、影视盗版、八卦政治。

硬规则：
- 链接必须来自 candidates.json，或亲自核实过的一手页面；严禁编造链接、价格、额度、截止日。
- 专题只能综合候选池里的条目，不得引入池外事实；数字不确定就写「未核实」。
- 不要报元信息：某源无新增、抓取失败、候选池多少条、用了几次工具。
- codes 里有邀请码的，原样写进对应条目。
- 一口气写完，不要中途截断；篇幅太长时优先保证快讯写完，要闻可压到 12 条。
- 全都不合格就只回 [SILENT]。
```

## 定时投递

任何能跑 shell 的调度器都行。cron 示例：

```cron
30 8 * * * cd /path/to/neo-news-bot && python3 collect.py >> run.log 2>&1
```

投递那一步不在这里：`candidates.json` 生成本身不产生副作用，编版与推送交给你的 agent / 脚本，避免把「抓取」和「发布」耦在一个进程里——重跑采集不会重复发消息。

## 调参旋钮

| 症状 | 先看什么 |
|---|---|
| 日报内容少 | `--stats`：采集层少 → 加源；候选够但日报少 → 编版规则在限流 |
| 日报太吵 | `obtain` 分级是否生效，`info` 是否被当成 `free` |
| 同一条反复出现 | `seen.json` 是否被误删，或跨源去重 key 太宽 |
| 某源长期 0 条 | `meta` 里的 `ERR`；社区源可能是反爬或限速 |
| 输出被截断 | 单条消息长度；9000 字符以上要考虑分层或分包 |
